# Mail actions and local drafts

Message actions sit above the selected email header. Reply/Reply all/Forward/Archive/Trash stay visible; narrow panes put Move, Read, Flag and Pin in More. Overflow reflects the current selection and disabled states. Global controls navigate Mail/Calendar, sync, accounts, alerts and drafts/outbox. New mail sits beside the folder heading. Import stays in File. Right-click and Message-menu actions use the same handlers. Controls disable during list changes or local mutations. The reader header follows selection immediately.


Delete always moves to Trash/Deleted Items. Deleting from Trash repeats that reversible operation. There is no permanent-delete command or provider hard-delete endpoint in this milestone. Moving stays within the message's account. Gmail removes Inbox/current source membership while keeping unrelated labels; Outlook moves the message to a folder using immutable IDs. Gmail stars and Outlook flags share the Flag control. Pins are local to Square Mail and order messages before unpinned rows through indexed queries. Automatic reading marks an unread message read after two seconds of ready content in the active, visible reading window. Selection changes, hidden/inactive windows, sheets, sleep and Calendar cancel the delay. Message > Mark read automatically after 2 seconds saves the global preference. Keep unread in the message actions/More or right-click menu stores a local per-email hold. Manual Mark unread does the same. The hold survives navigation, reopening, restarts and provider refreshes until explicit Mark read clears it. It is local to this Mac; the ordinary unread flag syncs through the durable offline queue when changes are authorised. Holding an already unread email needs no remote work. Schema 6 adds one flag without rebuilding the search index.

Actions update the local cache and durable queue in one SQLite transaction. Up to 100 pending actions are retained. Unstarted read, flag and placement changes coalesce independently for each message, allowing several offline operations without a new task per click. Sync replay reapplies pending projections. Cancel restores an unstarted change; provider work that has begun requires resolving its outcome. Errors and retry state are visible in Drafts / outbox. Manual retries preserve backoff. Gmail archive keeps other labels; folder memberships remain provider-specific.

The native plain-text composer supports To, CC, BCC, reply, reply-all and text forwarding. It respects Reply-To, removes the account's own address and duplicate recipients from reply-all, and never copies original BCC. Gmail replies preserve threadId, Message-ID, References and In-Reply-To; Outlook uses provider reply/reply-all draft endpoints. Quoted text preserves nested quote markers, bullets and separators, with a 256 KiB quote limit. Forwarding includes text only. Original attachments are omitted and the send review states this. Rich text, adding attachments, signatures, aliases and editing provider-owned drafts are future work.

Drafts autosave after 750 ms without edits, or through Save draft/Command-S. Closing, replacing the composer, quitting or disconnecting asks about unsaved changes. Edit versions avoid full-body encoding/comparison on every keystroke. At most 100 local drafts are retained, with a 1 MiB text limit, 100 recipients and a 2 MiB stored payload limit. Bodies load only when a draft opens; workspace lists contain summaries. An uncached original body needs opening online first. Replies created from old caches may need online metadata before sending. Local drafts are not synchronised across devices.

Send shows a recipient review, saves the latest draft and queues a fixed snapshot. The outbox holds at most 50 messages. Gmail sends MIME with a stable Message-ID. Outlook creates a provider draft, persists its ID, updates only compose fields and then submits it. A successful API submission means accepted, not confirmed delivery. Completed receipts retain at most 200 entries per queue. If creation/submission might have succeeded but its response was lost, the operation stops as uncertain. It is never automatically resent. Check Sent and provider Drafts before using Resolve stopped to recover its text; sending that recovered draft can duplicate a message. Cancel before provider work returns a queued send to local drafts. Provider drafts created during interrupted Outlook submissions may need manual cleanup.

One existing app-owned scheduler alternates mail work, calendar writes and sync pages. Mail actions and sends also alternate. Local queries stay separate from bounded network work; no SQLite transaction spans HTTP. Disconnect with Keep offline cache pauses queued work and retains drafts. Remove local cache explicitly deletes that account's local drafts and queued/outbox work; its prompt states this after resolving unsaved edits. New sync/sends require the app running. In-flight network cancellation waits for the bounded socket timeout and cannot undo an already accepted request. Remote edits, dense backfill, wake/reconnect, all account variants and long-run memory still need live qualification.

## Separate consent

Existing sign-ins stay readable. Drafts / outbox has per-account Enable mail changes and Enable sending controls. Google uses gmail.modify, which also allows sending at the API level; Square Mail keeps an additional explicit send opt-in. Microsoft requests delegated Mail.ReadWrite for changes and adds Mail.Send for sending. Prior calendar write grants are retained when requesting new scopes. A different identity or incomplete incremental grant is rejected before replacing saved credentials. An omitted refresh token retains the prior token for the same client/account. No provider mutation or send occurred during agent qualification.

## Reader and calendar additions

Compact spacing in the reader reduces repeated blank lines and trims blank space around plain text. It preserves content-line indentation, bullets, quote levels and separators. It changes display/copy text only; stored mail is unchanged. Original spacing returns with one click. HTML remains passive and remote images remain blocked by default.

Calendar displays local date, time and time zone. Day/week views mark today's current hour and minute. Today retains its own header/date highlight while selection uses a separate ring or underline. One clock task updates at minute boundaries only while Calendar is active; returning to Mail stops it. Hidden functional checks cover clock replacement without changing the selected day. Visible focus/window-manager and long-run power qualification remain separate.

References: [Gmail threading](https://developers.google.com/workspace/gmail/api/guides/threads), [Gmail message methods](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.messages), [Graph move](https://learn.microsoft.com/en-us/graph/api/message-move), [Graph reply drafts](https://learn.microsoft.com/en-us/graph/api/message-createreply?view=graph-rest-1.0), [Graph updates](https://learn.microsoft.com/en-us/graph/api/message-update?view=graph-rest-1.0), [Graph send acceptance](https://learn.microsoft.com/en-us/graph/api/message-send?view=graph-rest-1.0).

Outlook Trash/Archive can queue before folder discovery completes. They use the cached physical folder ID when present, otherwise Graph's documented `deleteditems`/`archive` names. The request remains a move, never permanent deletion. See Microsoft's [move operation](https://learn.microsoft.com/en-us/graph/api/message-move?view=graph-rest-1.0) and [well-known folders](https://learn.microsoft.com/en-us/graph/api/resources/mailfolder?view=graph-rest-1.0). A message removed during sync produces a selection/refresh message instead of a raw SQLite error. Synthetic HTTP tests cover missing-catalog Trash; live user mutations remain a separate gate.

Automatic reads use the same durable offline read lane and separate provider write consent as manual actions. One cancellable dwell task and one bounded local writer update header flags without rerendering bodies or waiting for HTTP. Background list refreshes retain the selected body and its delay. When a read message leaves the Unread filter, the reader clears without selecting the next message; background refresh cannot mark the list in a cascade. Existing action limits and in-flight conflict handling apply. Failures stay visible and do not retry in an idle loop.

The right-hand selected-day agenda shows a nonselectable Now divider on today and elapsed progress beneath ongoing events. The existing minute clock updates it without network queries or another timer. Other dates and the tabular below agenda have no time divider.

Successful Trash, Archive and Move select the next message in the displayed order, or the nearest previous message at the end. New arrivals do not reset selection to the head. This also advances in All mail when the acted-on row remains visible. A remaining sole row stays selected. Empty final pages return to the last row of the preceding page. Selection and scroll are anchored to the bounded visible page; a newer user selection or changed folder/search takes precedence. Failed or cancelled actions do not advance. Automatic reading in Unread retains its separate no-advance rule.

Queue send closes the composer and opens Drafts / outbox with the queued message and its account selected. Refresh preserves that selection and displays blocked/error details. Queued does not mean sent. Sending requires its separate user grant; granting it resumes queued work, so avoid queueing a duplicate. The panel retains at most20 recent accepted-send summaries, with no bodies, and distinguishes provider acceptance from delivery confirmation. Completed sends cannot be retried/cancelled from these receipts. Sent-folder indexing follows normal provider sync.

An independent outbox banner identifies the account and requested permission while browser sign-in is waiting or cancelling. Its Cancel sign-in button shares the main toolbar cancellation path and never cancels queued mail or an accepted send. The banner survives refresh/reopening, errors remain dismissible, and controls recover after completion/cancellation. Accepted-send details stay in the separate message status area. Account-connection flows that have not identified an email say that the account is being chosen in the browser.

## Selection, Undo and compose

The native message list supports Shift-click ranges, Command-click toggles and Command-A for the current page, at most250 headers. Delete/Backspace in that list moves selected messages to Trash and selects the next remaining row. Text fields keep their normal deletion behavior. Right-click preserves an existing selection. A multiple selection shows its count without fetching bodies or starting automatic-read timers; Reply/Forward require one message. Batch operations accept up to100 messages, with a visible limit. Move requires one account; Trash/Archive/Read/Flag/Pin work across accounts.

Edit > Undo / Command-Z reverses the last manual mail action or batch in the main window, while native field/body editing keeps its own Undo. There is no mail Redo yet. Twenty undo groups are retained with bounded header-only data. The UI history lasts for the app session. Pending changes restore their previous queue/projection atomically; completed changes enqueue an inverse. In-flight actions wait for their result. Changed messages, missing receipts/folders and a full queue reject the whole undo with a status message. Sending, provider deletion and automatic read dwell are excluded. Undo never permanently deletes mail.

Compose uses the shared rectangular caption and action bar, with Send review, Save draft and Close above recipients/body. Command-S saves locally; Command-W follows the unsaved-close prompt. Automatic save keeps keyboard focus and text editing active. Versioned snapshots leave newer edits dirty until a subsequent save completes. Save/Send disable during a save, then recover. Native text undo, recipient review and offline outbox behavior stay separate from mailbox Undo. Plain text and local-only drafts remain the current compose limits.
